# 模拟面试题去重与录音问题复用

## 题目去重

- 题目先进行 Unicode 兼容归一化、大小写归一化以及标点/空白清理。
- 后端用字符二元组相似度做保守的近似重复检查；同轮新题会与本轮已选题及该简历历史模拟面试题比较。
- 生成结果去重后不足 20 题时，后端会额外请求模型修复一次；仍不足 20 道不同题目则返回 502，不会把重复题目写入面试会话。
- 同一知识点允许再次考察，但应更换考察角度。此机制是文本相似度防线，不等同于语义模型，极端改写仍可能需要后续语义去重升级。
- 题目历史来源为 PostgreSQL 的 `interview_question` 与 `interview_session`，按 `resume_id` 跨轮排除。

## 统一个人面试经验 RAG

- 真实面试录音复盘提取面试官问题、候选人回答、参考/改进答案、优势、薄弱点和建议；模拟面试结束后也会自动把逐题回答、评分、弱点与报告写入 PGVector。
- 两类经验通过统一的 Interview Memory 检索入口供新一轮出题使用，开始模拟面试时不再选择单个录音。
- 新录音生成报告后，如果当前选中简历可用，会自动建立向量索引；已有历史报告可在“历史录音资料库”点击“同步全部录音经验到 RAG”批量补齐。
- 批量同步只处理已完成复盘的音频。没有报告的音频需要先生成报告（会调用 ASR/LLM）；向量化会调用 Embedding，可能产生模型费用。
- 已索引记录会跳过；关联到其他简历的录音不会被跨简历移动；失败项目可单独重试。

## 数据库和调用说明

项目尚无登录/用户账户模型，现阶段以 resumeId 隔离个人经验。录音与模拟面试经验进入同一简历对应的 PGVector 检索范围；不同简历之间暂不共享。此次修改不新增数据库列，不需要 SQL 迁移。开发验证不会主动调用真实 ASR、LLM 或 Embedding；用户主动点击批量同步时会调用 Embedding。
